# WB05 真機驗收附錄（人類執行）

接續 wb02（5 項）與 wb03（4 項）。判定規則相同：**需錄影，CDP／模擬器
證據不採計**。本輪 4 項需要**帶筆的平板**（iPad＋Apple Pencil，或
Android 平板＋主動式觸控筆）。

| # | 項目 | 操作 | 通過標準 |
|---|------|------|----------|
| 10 | 筆優先 | 開白板（**不切繪圖工具**）→ 直接用筆寫一行字 | 筆一落下就出墨、跟手無明顯遲滯；手指在同一塊畫布上仍是平移 |
| 11 | 掌拒 | 手掌自然靠在螢幕上、用筆連續寫三行 | 筆畫不中斷、不分裂成多個節點；畫面不被手掌拖走；筆抬起後手指立刻恢復平移 |
| 12 | 壓感 | 由輕到重畫一條長線 | 線條粗細看得出變化；不支援壓感的筆則是均勻粗細（不得變成看不見的細線） |
| 13 | Split View | 橫向開白板 → 確認左側討論欄 → 按 ☰ 收合 → 再展開 | 討論與白板同時可用；收合後畫布補滿整寬；展開後回到原本比例；畫布視角不因收合而跳掉 |

## 這一輪最需要被真機推翻的假設

**Split View 的 900px 斷點**（design.md 有推導）。若在真機上發現 1024 直向
的 684px 畫布「還是太窄、寧可切 tab」，就把斷點提高到只涵蓋橫向 —
這正是真機清單存在的意義，不要用模擬器的視覺印象決定。

## 判定與後續

沿用 wb02 檢查點條款：全項通過才繼續留在自研引擎路線；任一項失敗有一次
7 天修復窗，逾期進強制 xyflow spike。第 10–12 項若因**裝置不支援壓感**
而無法驗，記為「N/A（裝置限制）」而不是 PASS。
