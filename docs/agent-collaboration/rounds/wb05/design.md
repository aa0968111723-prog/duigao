# WB05 — 平板／觸控筆輪 設計與實作

wireflow 的 PR-05 預告是「Split View（討論｜白板）、可收合側欄、Pencil」。

## 觸控筆：筆優先＋掌拒＋壓感

平板上「手寫」和「用手操作」是兩種輸入，混在一起是最常見的破壞性體驗。
規則與 Freeform／Notability 一致，使用者不用學：

- **筆優先**：`pointerType === "pen"` 一律進筆畫，**不必先切繪圖工具**。
  手指維持既有語意（平移／縮放／選取），繪圖工具開著時手指才畫。
- **掌拒**：筆按下期間所有 touch pointer 一律忽略（連 pinch 都不給）；
  筆抬起後有 250ms 寬限期 — 手掌常常比筆晚離開。滑鼠不受影響（桌機沒有
  手掌問題）。
- **壓感**：`content.pressures` 與 `points` 等長，渲染成**逐段線寬**。
  單一 path 畫不出粗細變化，而粗細正是筆相對於手指的價值。沒有壓感資料
  （`pressure` 為 0 或缺）就退回基準寬度 — 不會變成 0 寬看不見。

仲裁邏輯在純函式模組 `pen.ts`（`shouldRejectPointer`／`widthForPressure`／
`segmentWidths`），單元測試 5 條直打純函式；e2e 在 1024×768 觸控環境驗
真實 pointer 事件序列（筆畫到一半手掌落下，筆畫不得斷成兩個節點）。

## 平板 Split View（≥900px）

- 左側常駐討論欄（340px），右側白板 Focus 層讓出左緣。**手機完全不變**
  （斷點以下 `display:none`，行為與 WB04 相同）。
- 可收合：頂欄的 ☰ 或側欄的 ✕，收起後畫布補滿整寬。
- 工具列在平板轉**右側直欄** — 平板上拇指構不到底部中央。節點／區塊的
  情境列維持底部橫列：它是「對這個東西做什麼」，擺在內容附近比擺側邊直覺。
- 768×1024（直向 iPad）**不進 Split View**（斷點 900）：340px 側欄會讓
  畫布只剩 428px，比切 tab 更糟。

### 為什麼是 900 而不是 768

畫布寬度是白板的核心資源。900 以下拆兩欄，兩邊都不好用；900 以上（含
1024 直向與所有橫向平板）拆開才划算。這條線是可以被真機推翻的假設 —
真機清單有對應項。

## 共用討論面板的實作

`RoomDiscussion` 在 `pane === "board"` 時**自己 return null**（手機是 tab，
同時只有一個）。平板側欄是同時顯示，所以要明確覆寫 `pane: "chat"` —
沒覆寫時側欄是空的（這條是 e2e 抓到的，不是想出來的）。
渲染改成 `renderDiscussion(paneOverride?)` 函式（不是 const）：JSX 只在
渲染時求值，宣告順序就不受 `createPoll`／`openBranch` 這些後面才宣告的
相依限制。

## 誠實記錄

- **平板的可用畫布比例低於手機的 75% 門檻**：1024 寬扣掉 340px 側欄後
  畫布約 67%。這不是退步 — 是把螢幕換成「同時看得到討論」的刻意交換，
  而且一鍵可收合回滿版。ADR-013 的 ≥75% 檢查點是**手機**的不變式，未變。
- **視覺基準重切**：`tablet-1024` 的兩張（board-20／selected）因 Split View
  改版重切；390／412／768 三個尺寸完全未動（證明手機路徑沒被碰到）。
- **筆的橡皮擦端（eraser）未做**：`pointerType === "pen"` 但 `button === 5`
  的反轉端要對應「擦除」，需要筆畫級刪除 UI，屬後續。
- **筆畫平滑（Catmull-Rom／曲線擬合）未做**：目前是折線。抽點門檻已把
  抖動壓下去，但快速書寫仍看得出稜角。
- **懸停預覽（pen hover）未做**：Apple Pencil hover 需要 `pointerover`
  的獨立處理，且只有部分裝置支援。
