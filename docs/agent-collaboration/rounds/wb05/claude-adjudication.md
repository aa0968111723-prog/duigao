## 最重要的一條：我把「筆優先」做成了「筆只能畫」

**[high] 觸控筆再也選不到、拖不動、編輯不了任何節點**

我的 `pointerdown` 在 hit-test **之前**就短路：`kind === "pen"` 一律進筆畫。
結果是平板使用者拿著筆時，WB02／WB03 建立的全部互動（選取、拖曳、雙擊
編輯、連線、框選、套索）**對筆全滅** —— 而平板上沒有第二種指標可以退回。

「筆優先」的正確語意是「筆**預設**就是畫」，不是「筆只會畫」。修法：
`penDraws = kind === "pen" && selectTool === "off" && !connectMode` ——
工具列選了別的工具時筆要聽話。e2e 反例：選「框選」後用筆點節點，必須
選到節點且**不得**長出筆畫。

## 掌拒的四個破法（Grok F1 ＋ 自審三條，全部成立）

- **吞掉已追蹤 pointer 的 up → 手勢層永久卡死**：手指先按著（已進
  `gesture.pointers`）→ 拿筆寫 → 手指抬起時 up 被掌拒丟掉 → 那個 pointerId
  永遠留在 map → 下一次單指按下就是「第二指」→ 直接進 pinch，畫面暴縮。
  修：掌拒**只擋新的 touch**，已在狀態機裡的 pointer 一律放行。
- **關板後狀態殘留**：元件不卸載，離開時若還握著筆，`penPointerId` 留著 →
  重開板後所有手指被永久拒絕。修：離開 Focus 時重置筆與筆畫狀態。
- **drawMode 開著時反向傷害**：手指先起筆畫，筆落下時被當成第二個 pointer
  → pinch。修：筆落下時作廢手指那筆，讓筆接手。
- **frame 把手不受掌拒管轄**：手掌壓在區塊標題帶上會把整個區塊連同成員
  節點拖走。修：`beginFrameDrag` 也走掌拒。

## 版面（Grok F2/F3/F5 ＋ 自審三條）

- **[high] 側欄討論無法捲動**：主討論靠整頁捲＋fixed composer；側欄是固定
  高度容器，feed 沒有自己的捲軸 → 看不到舊訊息，訊息一多連輸入框都被裁掉
  （e2e 只驗 feed 存在、新房又是空討論，所以假綠）。修：feed 自己捲、
  composer 改 static。
- **[high] 手機橫向誤進 Split View**：iPhone Pro Max 橫向 926–956px **寬**
  但只有 ~430px **高**。斷點只有 `min-width: 900px`，註解卻宣稱「非粗指標
  手機」—— 註解在說謊。修：加 `and (min-height: 600px)`，並新增
  926×428 的 e2e 章節驗它。
- **[medium] 工具列浮在畫布上，蓋住的節點點不到**：`position:absolute;
  right:10px`。修：把畫布與工具列包進 `.wb-focus-main`，平板時工具列是
  **版面的一欄**而不是覆蓋層。視覺 diff 可見被蓋住的節點露了出來。
- **[medium] 收合側欄畫布跳 340px**：修法是只在**使用者切換側欄**時補償
  camera（讓畫面中心的內容留在原地），**刻意不掛在 ResizeObserver 上** ——
  掛載期間的量測序列（0 → 全寬 → 讓位後）也會被當成變化，開板的初始視角
  就變成競態的產物（視覺基準會抖）。
- **[low] sheet 以整個 viewport 置中，左半壓在討論欄上** → scrim 也讓位。
- **[low] 側欄在手機也掛載（只是 display:none）**：多掛一份完整
  RoomDiscussion＝重複的 outbox／捲動／焦點副作用；而且進板第一格會出現
  「畫布已讓位、側欄還沒掛」的空白帶。修：新增 `useIsTabletUp()`，掛載與
  CSS 斷點**同源**（同一組條件字串），`.wb-focus` 的讓位 class 也由同一個
  狀態驅動 —— 不會再有中間影格。

## 壓感（Grok F6 ＋ 自審一條）

- **[medium] `pressure = 0` 被當成「沒有壓感」→ 最輕的接觸畫成最粗**，
  起收筆的漸細整個反過來。規格上不支援壓感的筆按下時回報 **0.5**，所以 0
  一定是真實的最小壓力。修：只有 `undefined` 才是「沒有資料」。
- **[low] 預覽固定 3px、抬筆才變逐段線寬** → 預覽也用 `segmentWidths`。

## 我自己寫的 e2e 假綠（自審抓到，最該記）

**[high]「掌拒」那條斷言在拿掉掌拒之後同樣會綠。**

我驗的是「freehand 節點數 === 1」——但筆畫路徑與手指路徑本來就各走各的，
沒有掌拒時筆畫**照樣**會完成，這條斷言驗不到任何東西。真正會變的是
「手掌有沒有被當成第二指去縮放畫面」。修：改驗 zoom 在整段筆畫前後沒被
動到（沒有掌拒時手掌會觸發 pinch → zoom 改變 → 紅）。

這是本專案第三次出現同一類問題（WB03 的 overlay 只驗 DOM 存在、WB04 的
測試從未被型別檢查）。斷言要問的永遠是：**這條在功能壞掉時會紅嗎？**

## 完整結果回來後的複查（誠實補記）

自審 workflow 的驗證階段跑了約 6.5 小時，**在我修完一輪之後才結束** ——
所以驗證者審的是修復前的程式碼，共 13 條存活。我逐條對修完的現況重新
查證，結果分三類：

**已修（10 條）**：筆優先短路、掌拒吞掉已追蹤 pointer 的 up、drawMode 手掌
先落、pressure=0、frame 把手不受掌拒與筆優先管轄、Split View 下「打開來源
訊息」關掉白板、sheet 壓在討論欄上、進板第一格空白帶、手機仍掛隱藏
RoomDiscussion、e2e 掌拒假綠。

**以為修好、其實沒有（2 條）** —— 這是複查的價值所在：

1. **兩支筆同時**：我加了「已有另一支筆在畫就忽略」的守衛，但它寫在
   `penDown()` **之後** —— 而 `penDown` 已經把 `penPointerId` 覆寫成第二支
   筆的 id，於是 `penPointerId !== event.pointerId` 永遠不成立，守衛形同
   不存在。修：守衛提到 `penDown` 之前。
2. **筆狀態殘留**：我只在「離開 Focus」重置，**切板不會** —— 而元件根本
   不卸載（`!board` 只是改渲染 BoardList）。筆還在玻璃上時別人封存這塊板，
   新板上所有手指就被永久掌拒。修：切板的 effect 也重置。

兩條都補了會真的變紅的 e2e 反例（兩支筆同時寫、筆按著不抬就關板再開後
手指仍能平移）。

**未修 → 現在修了（1 條）**：逐段 `<line>` 讓一筆手寫變成數百個 SVG 元素。
新增 `strokeRuns()`：相鄰段的寬度落在同一個 0.5px 桶就併成一條 polyline。
壓感的視覺差異保留得住（0.5px 以下人眼分不出），元素數從「點數−1」掉到
「粗細真的變化的次數」—— 平穩運筆常常只剩個位數。e2e 斷言同步改成驗
「同寬的段有被合併」而不只是「有多種粗細」。

**教訓**：長時間的對抗驗證跑完之前就動手修，會讓「我以為修好了」與「驗證
者說還沒修」混在一起。修完之後**逐條對現況重新查證**是必要的，不是形式 ——
這次就抓回兩條真的沒修好的。
