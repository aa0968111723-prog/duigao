# WB06 — 白板上的 AI 協助 設計與實作

任務書的紅線：**AI 是可選擇的協助，不是自動執行者**
（Proposal → Preview → Apply → Audit）。

## 為什麼白板需要自己的一輪

房間層早就有完整的 AI 提案機制（`AI_ACTION_TYPES`、`applyGate`、0019 稽核）。
但白板上有兩個洞：

1. **Focus Mode 裡沒有 AI 入口**：WB02 為了把畫布撐到 86%，把 `AssetAiFab`
   在全螢幕白板時抑制了 —— 於是「在白板上問 AI」這件事根本沒有入口。
2. **白板提案是直接落板的**：`add_whiteboard_node` 一按套用就寫進房態，
   使用者在**看到結果之前**沒有機會反悔。這與「可選擇的協助」有落差 ——
   對話框裡的一行標題，不等於看見它會擺在哪、長什麼樣。

## Proposal → Preview → Apply → Audit

- **Proposal**：「更多 → 問 AI」帶著板上下文（選取的節點優先，沒選就用整塊
  板的文字）呼叫既有的 `askRoomContext`。回應裡只取 `add_whiteboard_node`
  型別 —— 投票／企劃／留言留給房間層的 AI 面板，不混進白板。
- **Preview**：建議以**虛線幽靈節點**畫在板上（`pointer-events: none`），
  底部確認列說人話（「會加上 2 個便利貼、1 個心智圖」）。
  預覽**不進房態、不寫 DB**：它只活在 Workspace 的 render 裡。
  按「取消」整批消失，什麼都沒發生過。
- **Apply**：**先自動存一張快照**（0025 的註解本來就寫著「AI apply 前自動
  一張屬 WB06」），再走既有節點管線寫入 —— OCC、op 帳、離線佇列都不繞過。
  快照失敗不擋套用，但 UI 訊息會誠實地不一樣（有沒有「套用前已存快照」）。
- **Audit**：每個提案一列 0019 稽核，並在討論串留一句「已把 AI 的 N 個建議
  放上白板」。人看得到、機器也查得到。

## 擺放：整齊，不聰明

`layoutPreview` 從視野中心往右排、三個換行。**刻意不做自動避讓**（找空位
塞）：那會讓使用者看不出 AI 想放哪裡，而且每次重算位置都不一樣。整齊的
一排比聰明的散佈好懂 —— 套用後使用者自己拖。

## 套用時重新產生 id

預覽 id 是本機臨時值。`planApply` 換成真 id 並同步換掉連線端點；端點對不到
的線直接丟掉（半截的線在畫面上是一條指向虛空的線）。
副作用是「同一份預覽套用兩次會得到兩批節點」—— 這是對的：重複套用是
使用者的選擇，不該被去重機制悄悄吃掉。

## 誠實邊界

- **只在雲端房提供**：房間 AI 需要 Supabase。本機房不掛 handler，
  Workspace 的入口判斷就是「handler 在不在」—— 不擺按不動的按鈕。
- **AI 不產生連線**：目前 `edges` 恆為空。`planApply` 已經處理連線的 id
  重映射，但沒有任何提案型別會產生它們 —— 這是為「AI 整理成心智圖」預留的
  路徑，**還不是功能**。
- **沒有「AI 改既有節點」**：只會新增。改寫既有內容需要欄位級的 diff 預覽
  與衝突處理，屬更後面的範圍。
- **預覽不持久**：重新整理頁面預覽就沒了（它本來就不該存在於任何人的
  資料裡）。這是刻意的。
