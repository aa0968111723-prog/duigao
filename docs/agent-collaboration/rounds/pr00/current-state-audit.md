### 風險

- Feature-map 'implemented' status is string-presence evidence (agent-feature-scan.mjs classifyFeature matches path+contains), so the gate's SOURCE_TEST_EVIDENCE check inherits the same weakness: a file containing the right words satisfies it without any behavior being tested — exactly how room-ai-context/asset-analysis reached 'implemented'.
- All browser E2E runs target mock-supabase.mjs, never a hosted Supabase; hosted-project drift (which migrations are applied in production) is explicitly 'unknown' by design (agent-layer.test.mjs:118-126 asserts productionMigrationHead='unknown'), so a production project stuck before 0010/0016 would pass every local gate.
- migrations.mjs silently exits 0 on developer machines without PostgreSQL binaries (migrations.mjs:53-64); only CI's REQUIRE_PG=1 makes it a real gate, so local green is weaker than CI green.
- Anonymous sign-in issues 'authenticated' JWTs (0010:33-34), so every 'to authenticated' policy — including the shared library read — is reachable by anyone who opens the app, making the cross-tenant library_assets exposure practical, not theoretical.
- Dual deploy configs (vercel.json + zbpack.json) invite a second, unmonitored deployment surface; only Zeabur is evidenced as live (README:176), and nothing pins which platform owns the domain users actually hit.
- The invite-fragment invariant check in agent:gate is regex-based against src/cloud/invite.ts (agent-release-gate.mjs:105-110); a refactor that renames inviteSource would fail the gate spuriously, while a second parser added in another file would pass it silently.
