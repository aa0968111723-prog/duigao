# PR #13 — 低摩擦回饋體驗

## 目標

讓從 LINE 點進來的使用者，就算只願意花 3～10 秒，也能留下有價值的回饋。

產品原則：

> 回饋越容易，參與的人越多；但不要把文宣討論區變成社群網站。

## 核心流程

### 新增修改點

手機主流程應縮成：

1. 點「修改點」
2. 點文宣位置
3. 可選一個快速原因（可跳過）
4. 輸入一句話
5. 送出

不要強迫填建議、分類、優先度。這些都放到「補充」裡。

快速原因建議：
- 看不清楚
- 位置怪怪的
- 圖片／素材
- 資訊有誤
- 我會這樣改
- 其他

## 一句話模板

主輸入框可提供可點擊的句子開頭：
- 我覺得這裡可以…
- 這裡有點看不清楚
- 如果改成…可能更好
- 我第一眼會注意到…

點擊後只帶入文字，不自動送出。

## 我也覺得

每個修改點支援「我也覺得」：
- 同一個人同一個修改點只能支持一次
- 再按一次可取消
- 顯示人數，例如「4 人也覺得」
- 不要把每次支持都變成一則聊天室訊息
- 排序可用支持數作次要訊號，但不要完全取代時間／優先度

建議資料模型：`comment_supports(comment_id, user_id, created_at)`，雲端環境下透過 RLS 保護。

## 簡單表態

修改點只保留非常少的表態：
- 👍 我也覺得
- 🤔 不確定

不要做完整 emoji reaction system。

視覺提案支援：
- 喜歡這個提案
- 保留原稿

第一版不做複雜投票與排行榜。

## 回覆修改點

每個修改點可以有簡短 thread：
- 直接回覆該修改點
- 顯示最近 1～2 則，更多再展開
- 手機不要把整個聊天 thread 長駐在海報上
- 回覆資料獨立，不要塞回主 `body`

建議表：`comment_replies(id, room_id, comment_id, author_id, author_name, body, created_at)`。

## 回饋完成感

送出修改點後：
- toast：「已收到你的意見 ✓」
- 可以短暫顯示：「目前 4 人提出 6 個修改點」
- 不要用積分、徽章、排行榜等 gamification

## 柔和文案

避免一直使用「錯誤」、「問題」等壓力較高的詞。

優先：
- 修改建議
- 想法
- 我會這樣改
- 還可以調整

必要時「資訊有誤」仍保留，因為它是明確問題類型。

## 看完後的單一提示

當使用者瀏覽一段時間、尚未回饋，且不在輸入／提案操作時，可以只出現一次輕量提示：

> 還有哪一個地方最需要調整？

按鈕：`＋ 新增修改點`

不要用 modal，不要每次進房都跳，不要變成問卷。

## 分享文案

LINE／系統分享預設文案應降低心理門檻，例如：

> 幫我看一下這張文宣，點需要調整的位置留一句話就可以，不用改原稿 🙏

分享者可直接使用，不要求再編輯。

## 手機 UX

不重做 MobileWorkspace。

修改點 composer：
- 第一屏只顯示快速原因 + 主 textarea + 送出
- 「補充建議、分類與優先」維持摺疊
- 快速原因要可單手點擊
- textarea 自動 focus
- keyboard open 時送出按鈕維持可見

修改點卡片：
- 問題／建議仍是主體
- 下方放「我也覺得 N」與「回覆」
- 不要塞太多 icon
- 已完成項目仍保持低視覺重量

## 雲端同步

PR #12 已有 Supabase cloud layer，本 PR 必須接入，而不是另做新的同步系統。

新增 entity 級同步：
- comment supports
- comment replies
- proposal preference（若實作）

要求：
- 即時更新
- offline 時 local queue
- reconnect 後 idempotent retry
- RLS 只能操作自己是 member 的 room
- 使用者只能新增／刪除自己的 support

## 本機模式

未設定 Supabase env 時：
- app 仍可 local mode
- support / reply 至少本機可用
- 不白屏、不丟技術錯誤

## 不能做

- 不重做手機 UI
- 不做完整社群 reaction system
- 不做公開留言牆
- 不做排行榜／積分／徽章
- 不做 AI 自動回覆
- 不做匿名公開房間探索
- 不改視覺提案 editor 核心
- 不重寫 PR #12 cloud layer

## 測試

至少驗證：

1. A 分享房間給 B
2. B 3 秒內能完成「快速原因 + 一句話」修改點
3. A 即時看到 B 的修改點
4. A 按「我也覺得」
5. B 即時看到支持數變化
6. A 取消支持，數字正確
7. B 回覆修改點，A 即時看到
8. C 沒有 invite 不可讀 supports/replies
9. offline 新增 support/reply，恢復後同步且不重複
10. 390×844、430×932、1280×800 無破版
11. `npm run build` 通過

## 完成定義

第一次從 LINE 點進房間的人，不需要理解整套工具，在 10 秒內能做到至少一件事：

- 點位置留一句話
- 對既有修改點按「我也覺得」
- 回覆一句
- 對視覺提案表態

如果還需要教學才能完成，就還沒完成。
